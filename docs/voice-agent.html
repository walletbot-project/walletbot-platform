Voice agent & tools

WalletBot lets users record their movements by talking to a Gemini Live session. The model dispatches a catalogue of typed tools — the same on every surface — to read and mutate the user's ledger. This page documents how the agent is wired and what each tool does.

Overview

The agent is a Gemini Live session running over a WebSocket. The user speaks; the model transcribes, plans, and emits toolCall messages. Each toolCall is handled by a local executor — Convex on the web, Drift on the native app — which returns a result that the model can speak back.

user ──┐ ▼ microphone ──▶ Gemini Live (WebSocket) │ │ toolCall { name, args } ▼ ToolExecutor ├── web → Convex queries / mutations └── native → Drift (offline-first); sync pushes later │ │ toolResponse { result } ▼ Gemini Live ──▶ TTS ──▶ user

Architecture

Tools are defined once in packages/shared and consumed in three places. The ephemeral session token issued by the backend is the single source of truth for what the model is allowed to call.

Shared catalog

packages/shared/src/tools/definitions.ts holds the Zod schemas; descriptions and typed TOOL_DEFINITIONS live alongside.

Token

convex/live/actions.ts serializes the catalog into the Live session's liveConnectConstraints.tools when minting the ephemeral token.

Web executor

apps/web/src/lib/agent-tools/executors.ts dispatches each tool to a Convex query / mutation via ConvexReactClient.

Native executor

apps/native/lib/voice/tool_executors.dart runs every operation against the local Drift database. Never calls Convex directly — the sync layer pushes writes when the device is online.

Balance reads

Per-account balances are computed in O(log n) time via two TableAggregates over transactions: an outflows aggregate keyed by the source account and an inflows aggregate keyed by the transfer destination. Every transaction mutation keeps both aggregates in sync.

Balance adjustments. The user tells the agent the observed balance (balanceAfter). The server computes the delta: amount = balanceAfter − currentBalance. balanceAfter is sacred and never modified; amount is just the bookkeeping delta.

Conventions

Every tool follows the same patterns so the model and the executors can be uniform.

  • idOrName. Account / category / tag references accept a UUID or a case-insensitive name. On ambiguity the executor returns { ok: false, error: "ambiguous", candidates: […] }.
  • Amounts. Decimal in user units (12.50); the executor converts to int64 cents internally.
  • Dates. ISO 8601 or natural-language ("today", "hoy", "yesterday", "ayer"). Omitted ⇒ now.
  • Currency. Inferred from the resolved account on every write. Never an LLM-supplied arg except in createAccount.
  • Return shape. { ok: true, … } on success, { ok: false, error: "…" } on failure. The model speaks the error to the user.
